IdentityTotpSelfServiceApi v4 전체 다운로드

이번 단계에서 코드 검토 중 실제로 2가지 보안상 문제를 발견해 수정했습니다.

비밀번호 변경 후 기존 Refresh Token이 살아 있던 문제 → 비밀번호 변경 성공 즉시 해당 사용자의 모든 Refresh Token 폐기.
동일 Refresh Token 동시 Refresh 경쟁조건 → Version concurrency token을 추가하고, 두 요청이 동시에 회전하면 최대 1개만 성공하도록 수정. 충돌은 재사용 공격으로 취급하여 해당 token family를 폐기합니다.
테스트도 추가했습니다. 기존 TOTP/Recovery/Login/Lockout/Rotation/Logout/SecurityStamp 테스트에 더해 비밀번호 변경 후 기존 Access·Refresh 무효화, 새 비밀번호 로그인, 관리자 정상 2FA Reset, 동일 Refresh Token 동시 요청, 429 Rate Limit 경계를 회귀 테스트에 포함했습니다.

SQL Server Migration도 001_IdentityTotp_v4.sql로 고정했고 RefreshTokens.Version 동시성 컬럼까지 DB 정의와 EF 모델을 맞췄습니다. GitHub Actions에서는 SQL Server 2022 → DB 생성 → 고정 Migration 적용 → Restore → Release Build → 전체 xUnit Test → TRX 결과 보존 순서로 자동 실행합니다. Windows에서는 scripts\run-regression.ps1로 동일한 절차를 실행할 수 있습니다.

VB6 샘플도 그대로 포함되어 있으며 Login → TOTP → Access/Refresh 저장 → Refresh Rotation → Logout/Revoke 흐름을 사용할 수 있습니다.

다만 현재 이 실행 환경을 다시 확인한 결과 dotnet과 sqlcmd가 설치되어 있지 않아 실제 컴파일/SQL 실행 결과를 성공이라고 표시하지 않았습니다. ZIP 자체와 필수 파일 포함 여부는 검증했습니다. 실제 .NET 10 + SQL Server 환경 또는 GitHub Actions에서 첫 실행하면, 이제부터는 실패한 테스트를 근거로 결함 재현 테스트 유지 → 코드 수정 → 해당 테스트 재실행 → 전체 회귀 테스트 순환이 가능하도록 만들어져 있습니다.
